# AGENTS.md — what is true about this repository

This is the artifact repository for the two-Radeon tensor-parallel work: the
raw measurements, the documents derived from them, the RCCL/hostcall
diagnosis, the probes and the build recipes. Public, MIT
(`github.com/cadamcat/dual-radeon-vllm`), bilingual (`README.md`,
`README.zh.md`). Its claim is that every number on every page recomputes from
committed rows, and the repository is built to keep that claim true.

Working principles and the multi-agent protocol are global (`~/.agent/`), not
here. Task records, reviews, drafts and worker logs live outside the repository
in the workspace and never enter it.

## Layout and entry points

```text
benchmarks/
  results.jsonl, results-2026-08-24.jsonl   raw rows, the source of truth
  <campaign>/README.md + logs/               one campaign each: its account, gated, with its evidence
  ledger.jsonl, prefill.jsonl, decode.jsonl  projections, generated by analyze/build_{ledger,prefill,decode}.py
  CAMPAIGNS.md                               generated index of every campaign directory (analyze/build_campaigns.py)
  analyze/verify_doc_figures.py              published-value, provenance and projection checks
  analyze/build_*.py, gen_*.py, chartlib.py  projections and figures
  harness/runner_{cuda,radeon}.py, telemetry.py, SCHEMA.md   the measurement harness and its record schema
  harness/test_runner_cuda.py, test_telemetry.py   laptop gates for the CUDA runner and the sampler's phase split
docs/
  *.md                                       published pages, hand-written (root-cause, vfio-atomics, open-questions, benchmarks, …)
  index.html, index.zh.html, articles/*.html generated by site/build.py from site/src/ — never edit by hand
site/build.py, site/src/                     the page sources; figures/*.json, chips.json, genfig-*.py
diagnose/                                    the reproducer: hipgate*.cpp probes, check-platform.sh, sweep.sh, kpack_hostcall.py
build/                                       the RCCL rebuild without hostcall and its symbol checks
deploy/                                      deploy-tp2.sh and the runtime stubs
patches/                                     vLLM patches, with README.md
```

Read first, by question: the failure and its cause → `docs/root-cause.md`;
the platform toggle → `docs/vfio-atomics.md`; what is *not* established →
`docs/open-questions.md`; how rows are shaped → `benchmarks/harness/SCHEMA.md`;
how the pages are built → `site/README.md`; what a directory measured → its
README, whose first heading is its title in `CAMPAIGNS.md`.

## Source of truth

When sources disagree, in this order:

1. committed raw rows and the verifier's recomputation of them;
2. the invariants in this file;
3. campaign READMEs and `docs/` pages that pass the gate;
4. the open task record in the workspace;
5. handoffs, `TODO.md`, comments, ordinary documentation;
6. an agent's assumptions or private memory.

A private agent memory is never a project fact: if it disagrees with a
repository or workspace file, the file wins and the memory is stale. Do not
silently resolve a meaningful contradiction between the first three; record
it and surface it.

## Invariants

- **Published quantitative results are checked against committed evidence**
  by `benchmarks/analyze/verify_doc_figures.py`. Checks read the actual published
  values and recompute from raw inputs; a constant copied into the verifier
  cannot detect an edited page. Changing a result and its check belongs in the
  same commit. The verifier's inputs must all be committed (it audits this itself).
- **Break tests cover distinct failure mechanisms**, such as a wrong unit,
  denominator, arm selection, missing input or changed published value. A new
  or changed mechanism must fail by name and without a traceback. Reusing a
  tested mechanism for more cells does not require a break case per cell.
  Break tests live in the workspace (`tools/break_*.py`) and run sequentially
  in disposable copies, never alongside another verifier in the mutated copy.
- **Document structure and phrasing are editorial choices.** Check numeric
  content, evidence identity, generated output and working links; do not pin
  heading order, list lengths, exact sentences or a mandatory article roster.
  Review experimental scope and recommendations against the evidence when
  they change. The check count is a run statistic, not a coverage target.
- **Verify from raw sources**, never from a summary: not a handoff, a task
  record, a README table or this file.
- **Assert the stack before measuring**: container image md5s, ROCm/vLLM
  versions, the commit a build came from, the checkpoint revision. A
  measurement whose stack was not asserted measures something unknown.
- **`ck(where, claim, value, tol=)` takes a relative tolerance**
  (`abs(value) * tol`). Never pass it for an absolute half-unit; the default
  is already half a unit of the last digit.
- **Verify the final change from a pristine worktree**, as well as the working
  tree. This catches uncommitted dependencies, including ignored evidence.
  One clean-checkout run at the delivery boundary suffices; intermediate edits
  and commits do not each need one.
- **Generated files are never hand-edited**: `docs/*.html`, `docs/articles/`,
  `benchmarks/CAMPAIGNS.md`, the three projection `.jsonl`s. Raw rows are
  never edited at all.
- **Concurrent tasks use separate worktrees.** Integrate local commits into
  the shared `main` only after checking its current state. Stage explicit paths
  only — never `git add -A` or `commit -a` — and read `git status --short` before committing.
  `git fetch` and read `origin/main..main` before any push.
- **Outward actions wait for the user**: push, upstream PR or issue comment,
  submission, publishing a draft. Local commits are unrestricted. No agent
  handles passwords or tokens.
- **Nothing of the agents' bookkeeping enters the repository.**

## Measurement environment

Campaigns run on the project's GPU guest (VM 101, 2× RX 7900 XT, gfx1100),
which is one exclusive resource:

- Before anything touches the GPUs: `sudo systemctl stop ollama llamacpp-hub`.
  Restore both in an **EXIT trap**, on every exit path, and confirm both cards
  are back to `27971584` bytes in `/sys/class/drm/card*/device/mem_info_vram_used`.
- One campaign at a time. Long jobs run detached with a progress file watched;
  never in the foreground of a session that can be interrupted.
- Without the lease a process may read `/sys`, logs and finished results; it
  may not start a container, a serve or a build.
- Run `benchmarks/harness/preflight_host_link.sh <campaign-dir>` before every
  campaign: the PCIe link state (x8 has happened) is part of the stack to assert.
- A result is scoped to the host that produced it. A PASS on the Mac says
  nothing about the guest (measured: the same fetch returns 200 here and 403
  there). Any Python fetching over the network from the guest sets an explicit
  `User-Agent`.

## Commands

Python 3 and the standard library; only the runners (`benchmarks/bench_runner.py`,
`benchmarks/harness/runner_radeon.py`) import `requests`. No package manager,
no build system, no CI in this repository.

```bash
# the gate over every published number                        COST: LOW
python3 benchmarks/analyze/verify_doc_figures.py

# the gate as a clean checkout sees it (the real test)        COST: LOW
git worktree add /tmp/pristine HEAD --detach
python3 /tmp/pristine/benchmarks/analyze/verify_doc_figures.py
git worktree remove /tmp/pristine --force

# projections, after new rows land                            COST: LOW
cd benchmarks/analyze && python3 build_ledger.py && python3 build_prefill.py && python3 build_decode.py

# the campaign index, after a README is added or retitled     COST: LOW
python3 benchmarks/analyze/build_campaigns.py

# the site: build docs/, or check that docs/ matches its source, writing nothing
python3 site/build.py
python3 site/build.py --check

# the harness on a laptop, no GPU                             COST: LOW
python3 benchmarks/harness/test_runner_cuda.py
python3 benchmarks/harness/test_telemetry.py

# a probe (on the guest, in the container)
hipcc -O1 diagnose/hipgate3.cpp -o hipgate3 && ./hipgate3
```

The verifier, site check and laptop harness are local CPU checks. Run the
verifier at the delivery boundary and during iteration when useful. Run the
site check or harness when the corresponding sources change.

## Architecture constraints

- Raw rows → projections → pages, one direction. Nothing is extrapolated;
  every row names the file it came from.
- The English and Chinese versions of a page share their figure blocks and
  chips from one JSON source; `build.py` asserts the two are byte-identical.
- A campaign directory is the experiment record: hypothesis, method, result
  and evidence in one README with its rows beside it. No separate experiment
  files.
- Logs are evidence: `benchmarks/**/logs*/**/*.log` is tracked by an explicit
  `.gitignore` negation; a log kept anywhere else needs its own negation or
  the gate breaks in a clean checkout.
- Compiled libraries (`*.so`) and probe binaries are never committed.
- A campaign earns a front-page mention only if it answers a question about
  the pair; otherwise it lives in its directory and in `CAMPAIGNS.md`.

## Commit messages

**Subject fits in 72 characters.** Not taste: git and GitHub truncate there.
Measured 2026-09-06 — 52 % of this repository's 298 earlier subjects overflow
it, and 13 of the 15 written that day did, so this is a correction, not a
description.

**The body is two lines by default**: what moved, and why — the why only when
it is not readable from the diff. For a gated change, name the relevant
validation and the failure mechanisms exercised. A rising check count is
not evidence of improved coverage.

Anything longer has to carry something the next person would otherwise miss.
The reasoning is not that thing. Its home is the gate's comment, the document
or the campaign README: committed, searchable, and where someone is actually
looking. A commit body is not a findable place — `6dc064d`'s story sits in a
commit body *and* in `verify_doc_figures.py`'s comment, and only the comment
earns its keep.

## Definition of done

A change is done when all of these hold:

1. `verify_doc_figures.py` passes in the working tree and once from a pristine
   checkout of the final change.
2. Published results added or changed are tied to committed evidence; new or
   changed checking mechanisms have a named failing break case. Scope and
   recommendation changes have been reviewed against the evidence.
3. If `docs/` or `site/src/` changed, `python3 site/build.py --check` is clean.
4. If a campaign README was added or retitled, `CAMPAIGNS.md` was regenerated;
   if rows landed, the projections were rebuilt.
5. Only explicit paths are staged, `git status --short` was read, and nothing
   was pushed without the user's word.
