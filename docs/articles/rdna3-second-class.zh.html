ROCm 内核的八个结论在 RDNA3 上收窄至三个，
而实测另一厂商排除了两个

RDNA3 上的八个结论按五条硬件轴分类；对照另一厂商、内核源码与宿主机拓扑逐一核验

本仓库自身的总结将 RDNA3 称为 ROCm 内核生态里的二等公民，并将八篇文章归于该标题下。但若按证据实际支持的范围归类，八个结论中只有三个确实如此。其余结论要么覆盖 AMD 全线，要么与厂商无关，要么完全不关 GPU 的事。分清各自的归属，正是技术诊断与宣泄情绪的分水岭。

摘要

这一论断确有其事，但涵盖的范围比表面看来要窄。真正属于架构特定的问题只有一份简短清单：这套硬件无法走通的注意力快路径，用类型闸门将常见 checkpoint 类别拒之门外的原生量化线性内核，以及某函数中只写进单一架构分支、却在另一架构中缺失的性能启发式规则。

最纯粹的实例仅有一行代码。对于同一个内核，use_rocm_custom_paged_attention 在 gfx11 上要求 gqa_ratio >= 3，在 CDNA 上则要求 >= 1。在被排除的区间里，该内核比绕过它而换用的兜底实现快 1.84 到 7.28 倍， 且两个区间彼此重叠。这道界限没有任何区分意义。

八个结论中有四个不是 RDNA3 的问题，实测的目的也正是为了厘清这一点。其中两个结论在不同证据下均表明与厂商无关：同一道注意力闸门在 A100 上实测显示，其在 50K 上下文时性能下降 61 %；此外，单线程编译设置经溯源位于一个所有平台均会执行的文件中。第三个问题覆盖 AMD 全线，根源在于 AMD 明确指出的某行内核代码。最后一个问题则是 PCIe 能力位限制，在裸机环境下同样会遇到。

十六条上游 issue 与 PR 中有一半属于其他开发者。 这套硬件发挥的最大作用，无非是充当了上游开发者手头缺少的那台测试机。

3不属于此类的另外四个

分量最重的那些实测，恰恰是将结论从这份清单中排除出去的测试。

两个结论经由实测另一厂商而确立 长上下文下投机解码性能塌陷，最初看似是 RDNA3 的问题。然而在租用的 A100 上测试同一模型时，走同一个 Triton 内核在 50K 下同样出现 61 % 的性能跌幅，且在没有该防护检查的后端上恢复了正常。同样，128 专家 MoE 跑出 15 tok/s 的极低吞吐，起初令人怀疑是 ROCm 缺少调优内核所致。实际原因却是 env_override.py 中一行在所有平台上均会执行的赋值语句。参见投机解码报告与另一篇 MoE 报告。
一个属于 AMD 全线，根源在 AMD 指明的一行代码中 权重加载速度甚至低于磁盘读取，根源在于 kfd_svm.c 直接从 VMA 读取访问模式。只读拷贝请求了写权限，从而破坏了所有常驻内存页上的 copy-on-write 机制。该内核文件并不针对特定架构。AMD 确认了这一机理，第三方开发者也在另一款显卡上复现了该故障。详见完整分析文章。
一个完全与 GPU 无关 所有 RCCL 集合通信在 dispatch 阶段崩溃，是因为卡上方的 PCIe 根端口缺少 AtomicOps 能力。该故障在裸机环境下同样能够复现，与系统中安装了哪款 GPU 毫无关联。对于虚拟机环境，修复只需一行宿主机配置。参见关于 RCCL 的分析文章。

第五个案例值得单独列出，因为它反映的是宿主机拓扑而非芯片本身。2D 注意力路径为每个 KV head 启动一个 workgroup；将模型拆分到两张卡上会使可用的 KV head 减半，导致计算饥饿程度加倍。这种性能惩罚属于张量并行的固有代价。此处作为实测单卡对照的 A100 运行着完全相同的内核，因此无需承担这笔开销。参见双卡对比分析。

4这套硬件最终证明的真正用途

这项工作共衍生出十六条上游讨论。其中的分布很能说明问题：八条来自本仓库，另外八条则属于外部贡献者；在这后者之中，本测试平台提供的是对方无法自行采集的实测数据。

这便是消费级显卡对此软件生态真实价值的客观总结。本测试的目的从来不是追求极致跑分：在没有 P2P、依靠跨 die PCIe 3.0 链路的 VFIO 客户机上运行，测出的绝对吞吐仅仅是下限。它们真正的价值在于填补实测空缺：为缺乏对应硬件的开发者提供实体机器，让那些仅在编译层面做过验证的测试计划得以经受实际运行的检验。

5没有被确立的部分

这个分类是一个判断

尽管各项倍数均可重算且每条依据均给出了事实支持，将结论归入特定硬件轴依然属于逻辑推论而非直接实测。八个结论中有两个可合情合理地归入其他类别：W4A16 类型闸门本质上是恰好位于特定架构内核中的常规缺陷；而缺失的 MoE 调优配置虽放在 RDNA3 评测中讨论，本质上却涵盖 AMD 全线。

一台机器，一代软件

所有实测均基于 VFIO 客户机上的 gfx1100，跨越两代 vLLM 与两个 ROCm 版本。这些结论是否适用于 RDNA4 并未做过实测；仓库架构笔记虽预期该生态缺口会延伸至该架构，但该断言仅来自对支持硬件文档的核对，而非基准测试。

这些缺口是否在收窄

测试期间仅有一项上游 PR 得到合并并解决了半个问题。这指明了改进方向，却不足以构成整体趋势。本文仅记录了测试当时 gfx11 支持的实际现状，并未衡量上游开发的推进速度。
