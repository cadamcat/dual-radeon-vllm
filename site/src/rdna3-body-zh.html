而测另一个厂商拿掉了两个

这里面有多少真的是 RDNA3 二等公民

这个仓库自己的总结说，RDNA3 在 ROCm 的 kernel 生态里是二等公民， 而八篇写作都挂在这个标题下面。按证据真正支持的范围重新分一遍， 八个里有三个是。其余的要么是 AMD 全线的、要么与厂商无关、 要么根本不关 GPU 的事 —— 而分清哪个是哪个，正是诊断和抱怨之间的差别。

__CHIPS__

摘要

这个论断是真的，而且比它看起来更窄。作为架构特有留下来的是一份很小很具体的清单： 一条这台硬件会掉下去的注意力快路径、一个类型门把常见 checkpoint 类别挡在外面的原生量化线性 kernel， 以及一条写在某个函数其中一个架构分支里、另一个分支没有的性能启发式。

最纯粹的那个实例是一行。use_rocm_custom_paged_attention 在 gfx11 上要求 gqa_ratio >= 3，在 CDNA 上要求 >= 1，用的是同一个 kernel。 而在被排除的区间里，那个 kernel 比它被越过去换来的兜底快 1.84 到 7.28 倍， 而且被排除区间与被放行区间重叠。这道界限没有分开任何东西。

八个里有四个不是 RDNA3 的问题，而把这一点说出来正是那些测量的用途。 其中两个是靠在另一个厂商上实测才被证明与厂商无关的：同一道注意力门在 A100 上于 50K 掉 61 %， 而那个单线程编译设置在一个每个平台都会跑的文件里。一个是 AMD 全线的，在 AMD 自己指出的那一行上。 还有一个是 PCIe 能力位，裸机上一样会中。

十六条上游线程里有一半是别人的。 这台硬件最有用的地方，最后证明是：它是那些正在修这些问题的人手上没有的设备。

3不属于这一类的那四个

最要紧的那些测量，恰恰是把一个结论从这张清单上拿下来的那些。

两个是靠在另一个厂商上实测才定的 投机解码在长上下文塌陷，看起来像一个 RDNA3 的故事 —— 直到同一个模型在一张租来的 A100 上经由同一个 Triton kernel 在 50K 掉了 61 %， 而换到一个没有这道门的后端就不掉了。而一个 128 专家的 MoE 被记作 15 tok/s， 看起来像 ROCm 缺调优 kernel —— 直到成因查明是 env_override.py 里一个每个平台都会执行的普通赋值。一篇和 另一篇。
一个是 AMD 全线的，在 AMD 自己点名的那一行上 加载权重比磁盘还慢，是 kfd_svm.c 从 VMA 上读访问模式， 于是一次只读的拷贝去要写权限，把每一个常驻页上的 copy-on-write 都打断。 那个文件不是架构特有的，AMD 确认了机理，而且有陌生人在另一块卡上复现了。 那篇文章。
一个根本不关 GPU 的事 所有 RCCL 集合通信在 dispatch 阶段失败，是卡上方根端口的 PCIe AtomicOps 能力问题。 它在裸机上一样复现，和插的是哪块 GPU 无关，而对虚拟机来说修复是一行配置。 那篇文章。

还有第五个值得单独点名，因为它关于机器的形状而不是芯片：2D 注意力路径每个 KV head 启动一个 workgroup，所以把模型切到两张卡上会把它们减半，被饿着的那条路径被饿得加倍厉害。 那是张量并行的代价，任何厂商的单卡跑同一个 kernel 都不付这笔钱。 那篇文章。

4这套硬件最后证明是干什么用的

这些工作产出了十六条上游线程，而其中的分法才是重点：八条是我们的， 八条是别人的 —— 在别人那些线程里，这台机器贡献的是一次他们做不到的测量。

这就是"一对消费级显卡对这个生态值多少"的诚实总结。不是跑分 —— 这里的绝对数字是下界，跑在一台没有 P2P、走跨 die PCIe 3.0 的 VFIO guest 上。 它的价值是充当那个缺口里的设备：修复的作者手上没有的那一台， 让一份"只做过编译验证"的测试计划变成一个运行时结果。

5没有被确立的部分

这个分类是一个判断

旁边每一个倍数都是重算的，每一条"理由"也点了证据，但把某个结论归到某条轴上， 是一个论证而不是一次测量。八个里有两个可以合理地被争到另一列去： W4A16 那个类型门是一个恰好落在架构特有 kernel 里的普通 bug； 而缺失的 MoE 调优配置是一个 AMD 全线的缺口，被包在一个原本属于 RDNA3 的故事里。

一台机器，一代软件

这里的一切都是一台 VFIO guest 上的 gfx1100，跨两代 vLLM 和两个 ROCm 版本。 其中任何一条在 RDNA4 上是否成立，没有测过；架构笔记说这个生态缺口会延伸到那里， 而那句话是对支持硬件清单的一种读法，不是一次测量。

这些缺口是否在收窄

这段工作期间有一个 PR 合入，关掉了某个结论的一半。那是关于方向的一个数据点，不是一条趋势。 这里没有任何东西测量 gfx11 的支持推进得有多快，只测了它站在哪。
